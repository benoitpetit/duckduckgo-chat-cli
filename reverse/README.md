# Duck.ai protocol notes

This document records the current protocol used by the CLI to communicate with Duck.ai. It replaces the older notes about the DuckDuckGo Chat endpoint, static VQD values, and hard-coded frontend headers.

## Current architecture

The CLI uses the live Duck.ai frontend as a small browser bootstrap:

1. Launch Chrome or Chromium in headless mode.
2. Open `https://duck.ai/`.
3. Fill and submit one synthetic prompt.
4. Intercept the resulting request to `/duckchat/v1/chat`.
5. Capture the current `X-Vqd-Hash-1`, `x-fe-signals`, `x-fe-version`, and user-agent headers.
6. Abort the synthetic request so it does not consume a chat turn or quota.
7. Send the user's request with the captured proof and a fresh durable stream.

The proof is intentionally captured at runtime. It is generated by the frontend and rotates, so hard-coded values eventually fail with `400`, `418`, `429`, or `ERR_INVALID_VQD` responses.

## Chat request

The production endpoint is:

```text
POST https://duck.ai/duckchat/v1/chat
```

The request uses the current frontend headers, the `duck.ai` origin and referer, and the current model identifier. The payload includes the conversation messages, `canUseTools`, `canUseApproxLocation`, `reasoningEffort`, and a `durableStream` object.

The durable stream contains:

- a random message ID;
- a random conversation ID;
- a freshly generated RSA 2048 public key encoded as a JWK;
- `RSA-OAEP-256` as the key algorithm.

The response is an SSE stream. The existing parser consumes the data events incrementally and exposes the assistant response to the terminal UI.

## Current models

The model IDs currently used by Duck.ai are:

| Model | ID |
| --- | --- |
| GPT-5.6 Luna | `gpt-5.6-luna` |
| GPT-5.4 Mini | `gpt-5.4-mini` |
| Claude Haiku 4.5 | `claude-haiku-4-5` |
| Mistral Small 4 | `mistral-small-4` |
| GPT OSS 120B | `gpt-oss-120B` |
| Gemma 4 31B | `gemma-4-31B` |

The CLI keeps aliases for the previous IDs so existing configuration files continue to resolve to a current model. Unknown model names fall back to `gpt-5.6-luna`.

## Error handling

The client refreshes the browser proof and retries once for transient anti-bot or rate-limit failures, including HTTP `400`, `418`, `429`, `ERR_INVALID_VQD`, and `ERR_CHALLENGE` responses.

If Chrome or Chromium cannot be found, the CLI reports that it is required for Duck.ai authentication. The supported executable names are:

- `google-chrome`
- `google-chrome-stable`
- `chromium`
- `chromium-browser`

## Validation

The protocol was validated with a real chat request after the migration to Duck.ai. The CLI returned `PONG` for the prompt `Reply PONG only`, with one successful interaction and no failed interactions.
